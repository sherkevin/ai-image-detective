# 第 10 单元：图像检索作品集与部署

## 从实验到作品集

一个完整视觉项目不只是模型文件，还包括数据、交互、评价和说明。高中课程的目标，是让学习者能把系统讲清楚。

## 作品集结构

| 部分 | 内容 |
| --- | --- |
| 项目目标 | 要解决什么图像检索问题 |
| 数据集说明 | 图片来源、标签、数量、隐私处理 |
| 表示方法 | 使用哪些特征或向量 |
| 检索逻辑 | 怎样计算相似度和排序 |
| 交互页面 | 用户怎样选择目标、调节权重、查看结果 |
| 测试集 | 至少 10 个查询 |
| 失败案例 | 典型误判和改进计划 |
| 边界说明 | 不能替代人工判断 |

## 展示脚本

一个好的展示可以按下面顺序进行：

1. 展示图片库；
2. 选择目标图；
3. 调节权重并观察排序变化；
4. 展示一次误判；
5. 解释误判原因；
6. 说明下一版如何改进。

## 部署注意

如果把项目放到网页上，应注意：

- 不上传未经授权的图片；
- 不展示个人隐私；
- 页面能在普通浏览器中打开；
- 说明项目只是学习工具，不是最终判断系统。

## 最终产出

结课作品应该让读者看见完整链条：从图片到特征，从特征到向量，从向量到排序，从排序到误判分析，从误判到改进。

## 深入理解：作品集要让别人能复现你的思路

一个完整的图像侦探作品，不只是一个能点开的网页。它应该让读者看见项目怎样从问题出发，怎样准备数据，怎样选择特征，怎样计算相似度，怎样评测结果，怎样分析误判，怎样继续改进。作品集的目标不是炫耀界面，而是呈现一条完整的学习和实践路径。

## 推荐文件结构

```text
project/
  README.md               # 项目说明与阅读入口
  data/images/            # 可公开展示的图片
  data/labels.csv         # 类别、来源、标注信息
  labs/playground.html    # 交互式检索页面
  docs/features.md        # 特征设计说明
  docs/metrics.md         # 评价指标与测试集
  docs/failures.md        # 误判案例与改进
  docs/presentation.md    # 展示脚本
```

文件结构可以根据实际项目调整，但不能缺少数据说明、评测记录和失败案例。没有这些材料，作品很容易像临时演示；有了这些材料，读者才能判断课程是否完整。

## 展示脚本

建议五分钟展示：

1. 说明项目问题：为什么要做图像检索；
2. 展示数据集：图片从哪里来，类别怎样定义；
3. 展示方法：从特征到向量，再到相似度排序；
4. 展示交互：输入目标图或文字查询，观察结果；
5. 展示误判：主动讲一个失败案例和下一步改进。

主动展示误判非常重要。它说明作者不是只挑成功截图，而是理解视觉系统的边界。

## 安全与版权检查

上线前要检查图片是否可以公开展示，是否包含人脸、姓名、联系方式、成绩、证件、家庭住址等敏感信息。对于自行拍摄的校园图片，也要避免展示可识别个人信息。页面说明中应写清楚：本项目用于课程学习和算法观察，不作为正式判断系统。

## 项目加厚任务

最后一次整理时，检查作品集中是否有“三类证据”：数据证据、算法证据和反思证据。数据证据说明图片和标注可靠；算法证据说明系统怎样计算；反思证据说明作者知道系统为什么会错、下一步怎样改。三类证据齐全，作品才有真正的厚度。
